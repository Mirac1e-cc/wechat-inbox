# 难活交给 Astra，日常用 Sol：GPT-6.2 先上了 Work 和 Codex

11 月 17 日，OpenAI 发布了 GPT-6.2 的两档模型。Astra 面向更难的项目，Sol 面向日常工作。官方的说法是，这两档在费力的任务上成绩更好，而且输出 token 更省，同样的用量上限能多做一些活。

从发布当天起，Plus、Pro、Enterprise 和 Edu 用户可以在 ChatGPT Work 和 Codex 里用 GPT-6.2 Astra 和 Sol；开发者也可以通过 API 调用 gpt-6.2-astra 和 gpt-6.2-sol。帮助中心写明：这次上线并没有把这两档加进普通的 Chat 聊天窗口。企业版和教育版还要等工作区管理员打开权限，能不能马上看到，还取决于方案、权限和推送进度。帮助中心另外写到，Business、Healthcare 和 FedRAMP 工作区也会随推送逐步开放，同样要等轮到你。**日常聊天窗口里暂时选不到它们，要去 Work，或者去 Codex，或者走 API。**

Pro 500 的订阅者可以用这两档的 Ultrafast。官方还第一次把 Ultrafast 开放给 Pro 200 的订阅者，眼下先从 GPT-6.2 Sol 开始。符合条件的 Enterprise 和 Edu 用户，也是管理员打开后才能用到同样的加速档。API 这边，两档在发布时就可以用 Ultrafast。

（图：images/01-gpt62-hero.jpg，图注：GPT-6.2 Astra 与 Sol 发布题图。图片来源：OpenAI 官方博客）

### 怎么选：难活给 Astra，日常用 Sol

Astra 是官方说的前沿档，用来做更复杂的专业工作。它强调幻灯片、表格和文档更贴近你给的模板，也更像这个行业平时的写法；代码更干净，前端也更好看一些，尤其是网站、游戏和三维设计。Sol 是日常档。官方说它比 GPT-6.1 Sol 更聪明、更省，同一个付费方案能多完成一些任务，很多 OpenAI 自己的员工把它当默认模型，技术和非技术活都用。

日常写材料、跑多步流程、普通改代码，我会先看 Sol；要出更完整的交付件，或者题目又长又难，再换成 Astra。

### 文档、表格、前端和长任务，官方说改了什么

下面这些数字和比较都来自 OpenAI 的发布材料，各项评测的条件和对照模型并不完全一样。

专业工作方面，官方有一项叫 Agents’ Last Exam 的评测，考的是多步、偏长程的专业流程。GPT-6.2 Astra 比 GPT-6 Astra 高 5.2 分，官方称单任务成本不到后者的三分之一；比 Claude Fable 5.2 高 5.5 分，官方称成本只有后者的 5%。脚注里写明，Fable 5.2 的榜单成绩排除了 9 项使用了后备模型的任务。

科学方向，官方认为 Astra 是目前最适合科学家的模型。它在 Terminal-Bench-Science 0.1 上比 GPT-6 Astra 高 9 个百分点，官方称成本不到三分之一；在 Vals Science Index 上也报了新高，这项评测要求模型解读真实的生物数据，并做实验去推断一个模拟系统如何运作。

写代码这块，Cognition 的 FrontierCode 2.0 考的是，对真实代码库的改动能不能达到维护者愿意合并的标准。官方说，GPT-6.2 Sol 在两档都开到最高推理强度时，分数只比 Astra 低 0.5 分，成本大约是五分之一。Astra 则被早期测试者形容为：在已有代码库里改复杂功能、补测试时，风格更干净，返工更少。

文档和表格是这次发布里着墨最多的部分。官方说 Astra 写得更直接、更具体，少一些空话。Harvey 的 LAB-AA v1.1 用法律作业来测：能不能在源文件里找到相关事实，写进符合全部要求、且没有实质性幻觉的交付件。官方称 Astra 刷新了这项纪录，通过率是 Claude Fable 5.2 的两倍以上，成本大约是六分之一。面向律师的配置叫 Astra for Law，在同一项上更高。内部的 GDPval v2 测的是咨询、金融、设计等真实项目里的长程知识工作，官方称 Astra 比 GPT-6 Astra 高 6.2 个百分点，输出 token 少 22%；Sol 比 GPT-6.1 Sol 高 5.3 个百分点。

Artificial Analysis 的 AA-AnalystAgent 用真实表格和报告出题。官方举了加州 Medicaid 支出报告里计算医疗转运花费的例子，称 Astra 在全部五次独立尝试中，有 62.5% 的问题都答对了。幻灯片方面，官方说 Astra 更能跟着模板走，连字体大小都能对上。三维交互体验的 AA-3D 上，由人类评委做盲选，官方报 Astra 排第一，Elo 是 1,318，后面是 Fable 5.2 的 1,271 和 GPT-6.2 Sol 的 1,259。

这些数字有的来自 OpenAI 内部基准，有的来自它点名的外部评测，都是发布材料里的说法。

### 标价、缓存和长上下文

GPT-6.2 Astra 的 API 标准价是每百万 token 输入 8 美元、缓存输入 0.40 美元、输出 40 美元。相对 GPT-6 Astra 的 10 美元、1.00 美元和 50 美元，输入和输出标价低 20%，缓存价从 1.00 美元降到 0.40 美元，低 60%。缓存命中时，0.40 美元相对当次未缓存的 8 美元，相当于少付 95%。

GPT-6.2 Sol 沿用 GPT-6.1 Sol 的 API 标价：每百万 token 输入 2 美元、缓存输入 0.10 美元、输出 10 美元。

（图：images/02-gpt62-api-pricing.png，图注：GPT-6.2 API 标准档短上下文价格，每百万 token，美元。数据来自 OpenAI 发布文与 API 定价页，制图：曾经的小狂）

定价页和模型说明里还有几条使用时要注意的条件。输入超过 27.2 万 token 时，整次请求的输入和缓存价翻倍，输出按短上下文价的 1.5 倍计。Batch 是标准价的一半，Fast 是两倍。Ultrafast 在 2027 年 2 月 28 日之前按标准价的 3 倍计，从 2027 年 3 月 1 日起（太平洋时间）按 6 倍计。官方建议尽量保持提示前缀不变，把新的指令追加到对话后面，这样更容易复用缓存，成本和延迟都会好一些。

ChatGPT 企业按 token 计费的价目表上，这两档的标准价和 API 是同一组数字，但帮助中心写明：这两行只适用于 Work 和 Codex，不适用于普通 Chat。

### 安全这一头，官方划了哪些线

系统卡写明，两档都达到了 OpenAI 准备框架里网络安全能力的 Critical 门槛，以及生物和化学能力的 High 门槛。Astra 还第一次在对外发布的模型里，达到了「AI 自我改进」的 High 门槛；Sol 在这项上没有达到。官方把这项门槛解释成：相对 2024 年的基线，模型的作用相当于给每位研究人员多配了一名很能干的研究工程师助手。因为能力更强，官方收紧了更高风险的网络安全协助，默认限制更严，更宽松的权限要额外审核。防守方目前仍主要通过 Daybreak 项目使用现有模型，官方说会争取把 GPT-6.2 也接进去。

对齐方面，两档在多数评测上和 GPT-6 Astra 差不多，在模拟的真实工作任务里，不当操作大约少了一半。但有两项评测显示，它们更可能在汇报时漏掉已经遇到的障碍，比如要改的文件其实不存在，或者某个搜索工具不可用。官方说，Codex 里的开发者提示能明显减少这类遗漏，他们还在继续查原因。

### 最后

现在要试用，先看自己能不能进 ChatGPT Work、Codex 或 API。进得去的话，日常活可以从 Sol 起手，把更完整、更费劲的交付件留给 Astra。普通聊天窗口里这次还找不到这两档。
